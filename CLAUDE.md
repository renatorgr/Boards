# CLAUDE.md

This file guides Claude Code (claude.ai/code) when working in this repository.

## What is here

Hardware and firmware for the **AgOpenGPS AiO v4.5** autosteer boards (Micro and Standard), made for Renato's
tractors, sprayer and no-till seed drill. Renato is a farmer and a beginner programmer: explain changes simply, and give him
text to paste into GitHub as a raw markdown code block.

## Rules for every change

- Code, comments, web pages and READMEs in **English**.
- Keep each file's header short: purpose, credits (where the code comes from, the original notices kept whole), one line
  pointing to the README changelog and the git log for the history, and the GPL v3 / SPDX line. No dated change lines in
  headers (they grew to 30 lines): the day's README changelog row and the commit message say what changed.
- The Teensy firmware **cannot be compiled in Claude's cloud sessions** (pjrc.com, arduino.cc and the PlatformIO
  registry are blocked). Say so in the pull request; Renato compiles before merging. The ESP32 programs
  (`Seeder/Seeder_ESP32`, `Sprayer/Sprayer_ESP32`) can: arduino-cli with the esp32 core fetched from GitHub.
- Do not rename `Firmware/vX.Y_AiO_WEB/` folders or the files in them: the module's web page and the XIAO
  page find new versions on GitHub by those names (see the firmware `CLAUDE.md`, "Common Gotchas").
- The firmware steers a tractor: safety code (WAS check, cut-offs, Keya heartbeat, watchdog) must keep working.
- Pull requests: one topic each, a short plain description of what changes for Renato and how to test it.
- `Sprayer/Sprayer_ESP32` and `Seeder/Seeder_ESP32` have the same code in the blocks marked `// ==== shared "name"` …
  `// ==== end shared "name"` (Wi-Fi, web helpers, network settings, PGN handling, relays). Change both the same way,
  or move a line out of the block: `.github/scripts/check_shared_blocks.py` compares them on every pull request
  (the "Shared code" check). What is only one module's (sensors, rate, the cable, the relays setting) stays outside.
- A change to `Firmware/v4.5_AiO_WEB` runs `Tests/Teensy_AiO/run.sh` (the "Teensy harness" check; about a minute, needs
  `g++-multilib`): it builds the firmware for the PC, so it works in the cloud too, and is not a Teensy compile. Run
  it before the pull request; a fixed bug comes out of `Tests/Teensy_AiO/known-bugs.txt`.
- A change to `Firmware/v4.5_AiO_WEB/v4.5_XIAO_ESP32` runs `Tests/XIAO_ESP32/run.sh` (the "XIAO harness" check; about
  two minutes, needs `g++-multilib`). Run it before the pull request. A change to the link between the two (`xLink.h`,
  `zXiao.ino`) may need its pretend Teensy to follow; a fixed bug comes out of `Tests/XIAO_ESP32/known-bugs.txt`.
- A change to `Sprayer/Sprayer_ESP32` or `Seeder/Seeder_ESP32` runs `Tests/ESP32_Modules/run.sh` (the "Module harness"
  check; about a minute, needs `g++-multilib`). Run it before the pull request. A change to what a program sends or saves
  may need the harness's bench to follow; a fixed bug comes out of `Tests/ESP32_Modules/known-bugs.txt`.
- README changelogs: one short row per day (a summary of up to 240 characters, with links to the sections that
  hold the details). `.github/scripts/check_changelog.py` checks them on every pull request (the "Docs" check).

## Boards (KiCad)

KiCad 7 installs in the cloud with `apt` (`kicad`, `librsvg2-bin` for PNG renders); `pcbnew` Python works for
edits and DRC. JLCPCB sites are not reachable from the cloud: part stock must be checked by Renato.
