# Known bugs: the harness reports them but does not fail the run. One per line:
#   <scenario>/<check key>[@<kit>]  why, and what fixes it
# Take a line out when the fix is merged (the harness says "passes now" when one is fixed).
short-settings-packet/ignored  Autosteer.ino ReceiveUdp takes PGN 252 (and 251) with any length over 4: the missing bytes come from the packet before. Check the length byte against the bytes read
eeprom-damaged/steer-only-when-asked  Autosteer.ino autosteerSetup takes the stored steer settings / config without a check: a 0xFF byte turns every flag on (an IBT2 driven as a Cytron with the relay inverted: full lock, nobody asked). Check flags 0/1 and counts > 0, else the defaults
eeprom-damaged/no-output-nan@f9p-ibt2  the same
subnet-while-steering/same-subnet-no-restart  Autosteer.ino PGN 201 saves and restarts even for the subnet the module is on, and while steering. Use netSetSubnet (zEthernet.ino), which refuses both
subnet-while-steering/refused-while-steering  the same
subnet-invalid/refuses-0  the same: netSetSubnet refuses 0.x.x, 127.x.x and 224 and up; PGN 201 takes them (the module then answers nobody)
min-above-max-pwm/max-limit  AutosteerPID.ino calcSteeringPID: with Min To Move above the Max Limit, the low PWM (Min x 1.2) is above it too and the PWM goes up to it. Keep lowPWM and minPWM at or below highPWM
